**Proposed policy**

- Accept only `source_kind=operator_manual` rate snapshots entered by #367 under its accepted management authorization contract; no existing runtime input path is assumed. The operator supplies publisher/reference, direct base/quote pair, exact quote (major quote-currency units per one major base-currency unit), publisher observation time `as_of`, operator retrieval time `retrieved_at`, and Steve-generated `recorded_at`; all are UTC instants serialized as RFC 3339 strings with explicit `Z` and millisecond precision, and require `as_of <= retrieved_at <= recorded_at`. Reject date-only/zone-less timestamps rather than inventing publication times. Currency identifiers must match accepted currency metadata from #298. The quote is positive and exactly representable under the separately accepted #164 arithmetic contract; never parse it through binary float. Reject missing provenance, unsupported/ambiguous pairs, or future `as_of`/`retrieved_at`. This defines Steve's accepted source kind, not an upstream publisher/feed.
- Only a direct quote is usable. Do not invert, triangulate, interpolate, or fall back to another pair. USD→USD is exactly 1:1 with no external snapshot.
- Proposed freshness: the producer captures `valued_at` at the attempt accounting event that fixes the chargeable usage, before enqueue/journal publication, in the same timestamp format. Carry that timestamp unchanged with the event through queue delays, retries, restart and replay; never substitute worker execution time. Only snapshots with `recorded_at <= valued_at` are eligible, even if newer quotes exist when the worker runs. Compare `valued_at` to publisher `as_of`; age 0 through exactly 72 hours (259,200,000 milliseconds) is fresh, age greater than 72 hours is stale. Reject future observation times. This is a conservative fixed operator policy, not a guarantee that a publisher has refreshed. Weekends/holidays can leave the latest quote older than 72 hours; in that case unknown is intentional, not extended freshness.
- Missing, stale, unsupported or rejected source→USD quote leaves canonical USD unknown while preserving source amount/currency. Missing/stale display-currency quote leaves local display unknown while preserving known USD. Unknown is never zero; never use latest FX to reprice a historical charge.
- At accounting valuation, capture `valued_at`, the exact rate, pair, source kind, publisher/reference, `as_of`, `retrieved_at`, and `recorded_at`; reports use that immutable evidence and its original validity result. They do not re-evaluate freshness against report time or replace captured unknown values when a rate later becomes available. Preserve previously captured known canonical USD if only display FX is missing. No FX network access, paid service, auto-refresh, or new operator role is added. Forwarding must not wait for operator input, FX refresh, or conversion: accounting remains deferred under §17; unavailable FX changes accounting completeness, not forwarding eligibility.
