## Decision A — latency EWMA

- Input is a `contract_version=1` span in #522 shape with `status=completed`, measured `duration_ns: u64`, and UTC end `observed_at`. Use only its closed v1 stage names.
- Provider/account grouping is allowed only on attempt-owned stages with the owning accepted IDs. Model grouping requires one explicit accepted model ID on the owning request/attempt; request stages cannot be joined to arbitrary attempts. Region requires authoritative accepted region metadata; otherwise the requested dimension is unknown.
- Proposed short/medium sample windows: trailing 60 s / 15 min, independently proposed here. Capture `now` once; membership is `[now-window, now)` by `observed_at`; monotonic `duration_ns` is never calculated from wall time.
- Deduplicate by #522 key `(request_id, attempt_id, stage)`. Identical same-key payload repeats count once; any differing field (version, status, offset, duration, or timestamp) makes the window unknown. Sort unique rows by `(observed_at, request_id UUID bytes, attempt_id [null first, then UUID bytes], stage ASCII bytes)` before folding; unsupported versions/stages make the result unknown.
- Proposed sample-weighted recurrence: initialize `y=x` from the first in-window sample; short `y=round_even((x+y_prev)/2)`; medium `y=round_even((x+7*y_prev)/8)`. Compute numerator in `u128`, round to nearest integer nanosecond with ties to even, store `u64`; do not use floating point. Time controls membership only; cadence affects sample weight.
- Recompute each window from its own ordered samples, so there is no carry across the window boundary. Proposed minimum is 5 unique complete samples; below 5 (including an empty window after older samples expire) or incomplete source coverage returns unknown, never zero. No separate freshness TTL is proposed: a sample remains eligible through the inclusive lower window boundary.
- The source must enforce idempotent uniqueness by the span key before window queries: exact repeats do not create rows; conflicting repeats are rejected and leave a conflict signal for affected windows. Until this guarantee and conflict signal are available, return unknown. Do not scan unbounded duplicate event history at query time. Bound each key/stage/window query to 10,001 unique eligible rows; 10,000 unique samples is the maximum computable set. In one consistent source snapshot, coverage bounds must span the full requested window and report no gap/known loss. Missing/unverified coverage returns unknown before checking overflow; verified coverage plus unique row 10,001 returns unknown/overflow. Never truncate eligible rows.
- Medium example: `8,16,24,32,40 ns` folds to `8,9,11,14,17 ns`; round after each update, not only at presentation.
- Example: short samples `10,30,50,70,90 ns` fold `10,20,35,52,71 ns` (52.5 rounds to even 52); return unknown at n<5, then 71 ns. Exact duplicate replay does not change the result; a same-key conflicting payload does.

## Decision B — reliability rate

- Count one terminal result per unique upstream `attempt_id`, attributed only to its accepted provider/account IDs and one explicit accepted model ID. Window membership uses the terminal outcome's UTC observation time: successful body completion or final observed failure, not request start.
- Success requires a normally completed, protocol-valid 2xx response body. A 2xx malformed response or provider/transport stream failure is failure; upstream 4xx (including non-429) is failure; 429 is failure and separately counted; upstream 5xx/retryable provider errors and transport/connect/time-out failures after outbound send begins are failures.
- Proposed #520 category mapping: `provider_status/rate_limited`, `provider_status/rejected`, `provider_status/server_error`, `protocol/malformed_response`, `transport/upstream_transport`, and post-send `timeout/upstream_timeout` are failures. Exclude caller `cancellation/request_cancelled`, `gateway/invalid_request|unsupported_request|invalid_configuration|service_draining`, and pre-send `overload/admission_limit` from both counts.
- Exclude caller-originated 4xx (`gateway/invalid_request`), caller-initiated `cancellation/request_cancelled`, and local `gateway/unsupported_request|invalid_configuration|service_draining` or `overload/admission_limit` before outbound send. Upstream `provider_status/rejected` counts as failure even for 4xx; a server/provider stream abort is not caller cancellation. Unknown cancellation origin/class/time or incomplete outcome coverage makes the window unknown.
- Use proposed trailing 60 s / 15 min windows and a minimum of 20 eligible attempts per window. Failure rate is exact `failures/eligible_attempts`; n<20 (including zero) is unknown, never a perfect rate. At n=20 with 18 successes, one 429, one 5xx, rate is `2/20=10%`; 20 successes is known 0%; n=19 is unknown.
- The outcome source must enforce the same pre-query idempotency/conflict rules using `attempt_id` as its unique key. Apply the same per-window 10,000-unique-outcome bound, 10,001-unique-outcome overflow probe, and same-snapshot full-window verified-coverage/no-gap/no-known-loss requirement as Decision A; coverage failure precedes overflow. Repeated identical attempt outcomes count once; conflicting outcomes for one attempt make the window unknown.

**Open acceptance:** Decisions A and B are independently acceptable. The classifications and span inputs above are proposed explicitly, not inherited as accepted #520/#522 contracts. #183's title is a one-observation update, while these window queries recompute bounded windows; re-size #183 to the recurrence only and keep window/coverage queries with consumers #258–#260. No backend, SLO/alert policy, or adaptive routing rule is selected.
